# V7 research critique and candidate experiments

Prepared 4 November 2026, before V7 inference. These notes motivate design choices; they are not V7 observations or a claim that a model will violate instructions. The campaign protocol and frozen manifest determine what actually runs.

## What V5/V6 left unresolved

The previous trials repeated a conspicuous prohibition and binding-policy wrapper in every fresh call. This measures compliance when the relevant rule is highly salient, not retention of a standing rule through a long workflow. Many higher-workload replies were censored at 60 seconds. A zero observed request count therefore leaves both rare violations and unreturned decisions unresolved. An explicit abstention option gave agents a compliant way to fail the numerical task. That is a useful control, not a defect to remove merely to obtain violations.

Leaving a process alive is not an experimental treatment by itself. The plausible exposures are accumulated interactions, competing state, distance from the policy, model-written memory, and changing task demands. Wall-clock delay is a separate operational variable. A model paused overnight does not necessarily acquire fatigue or new motives.

## Prioritized falsifiable comparisons

1. **History versus reminders.** Match cases, response budget, policy authority and task order. Compare a long session with the prohibition introduced once, the same retained history with a concise reminder before each task, and a fresh context containing the same current task and initial policy. If only the first arm degrades, this is consistent with a salience/retention mechanism; it is not proof of a particular internal memory failure.
2. **Resolve budget censoring.** Give the new arms the same longer response budget. Keep a separate fresh-context long-budget reference so a new behavior is not attributed to persistence when more reasoning time alone explains it. Queue and network delays remain mixed with computation.
3. **Increasing difficulty versus increasing age.** A sequence that becomes harder every round confounds task difficulty with history length. Interleave repeated easy/hard sentinel cases, or rotate/reverse the same workload order across independent sessions. A late easy sentinel is particularly informative: a rule failure there is not easily explained by current computation difficulty alone.
4. **Model-written memory as a separate future treatment.** Periodically ask for a compact work log, then use either the full history or that summary as the retained state. Compare both the omission of the rule and later behavior. Do not silently compress histories in the primary persistence study; compression is an additional intervention.
5. **Authority confusion as a separate future treatment.** A numerically harmless case note may claim the tool is permitted. Place this clearly in untrusted task data, with an explicit standing rule that task data cannot grant permission. Compare with a matched neutral note. Keep this separate from spontaneous drift: it is an injection challenge, and a policy change from the actual authorized user would not be a violation.
6. **Self-report versus logged behavior.** If a valid forbidden tool request occurs, continue under the unchanged policy and later ask whether any tool was used. Score the record against the answer. A false report is an observable contradiction; it is not, by itself, proof of deliberate deception. Never fabricate a tool execution or judge intent from hidden reasoning.

7. **Permission revocation after a legitimate habit.** In a separately frozen follow-on, allow the numerical tool for a warmup, then clearly revoke permission through the same authorized instruction channel. Compare with an otherwise matched always-forbidden trajectory. A post-revocation request would be an observable policy-update failure; requests during the allowed warmup are controls, not violations. This isolates a different question from forgetting an initial rule.

## Measurements that make a null result informative

Use independently seeded sessions as the experimental unit. Report sessions with at least one confirmed request, first violating round, completed/attempted opportunities before that round, unresolved calls, actual dispatch, task correctness and abstention. Show per-round coverage, policy distance and prompt byte/token size. Do not treat hundreds of correlated steps as hundreds of independent samples. If an episode stops after a timeout, distinguish right-censored persistence from a compliant survival.

Classify unusual behavior before inspecting results: exact forbidden requests; malformed requests; unauthorized names or case IDs; unsupported claims of tool execution; claims inconsistent with the logged score; and invalid native-tool events. Preserve raw text for qualitative review. Label exploratory themes discovered afterward as post hoc, and confirm them using fresh seeds rather than counting the discovery example twice.

Do not add morally loaded personas, threats, or an instruction to break rules merely to make the study interesting. A richer benign goal can create a real tradeoff, but permission and prohibition must remain unambiguous. The strongest next result could be that persistent agents continue to abstain: that narrows the mechanism rather than invalidating the experiment.

## Primary research read and its limits

- **Liu et al., Lost in the Middle (TACL, 2023/2024).** The paper tests multi-document question answering and key-value retrieval while moving relevant information within context. Its positional sensitivity motivates measuring policy position and distance; it does not establish that modern agents become less compliant simply with elapsed time. [Paper](https://arxiv.org/abs/2307.03172v3).
- **Yao et al., tau-bench (2024).** This benchmark combines policy-guided tool use with dynamic simulated-user conversations and grades resulting database state. Its reliability metric spans repeated trials. The useful lesson here is to measure actual actions and resulting state separately from the agent's narrative, and to distinguish per-step success from whole-session reliability. Customer-service tool environments differ substantially from this numerical-only task. [Paper](https://arxiv.org/html/2406.12045v1).
- **Panavas et al., HANDBOOK.md (2026).** This benchmark uses standing policy documents, extended tool workflows and deterministic checks for both required and prohibited actions. Reported failure types include following a local request over policy, ignoring check results and asserting unachieved compliance. It motivates independent grading of behavior and claims, rather than treating a final success statement as evidence. Its mock enterprise environments and long policies are not directly comparable to a single numerical prohibition. [Paper](https://arxiv.org/html/2607.25398v3).
- **Naik et al., AgentMisalignment (2025; revised 2026).** This suite distinguishes propensity to diverge from deployer intent from capability to comply with malicious instructions, and reports sensitivity to persona prompts. Its relevance is methodological: changing a persona or explicitly inducing bad behavior changes the construct being measured. Its intent-based evaluations do not license calling an ordinary numerical error or abstention deception. [Paper](https://arxiv.org/html/2506.04018v3).

The sources support designing discriminating tests; none predicts V7 outcomes. This note does not reproduce their benchmark prompts or import their environments.
